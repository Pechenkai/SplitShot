# Техническое задание: Веб-приложение "SplitShot / BarSplitter / PartyHelper"

## 1. Идея проекта
Веб-сайт, позволяющий упростить расчет чека в баре/ресторане для компании людей. Никаких калькуляторов под рукой. Просто сканируем чек, отмечаем, кто что пил/ел и скидываем деньги человеку, который оплатил счет. После решения финансовых вопросов приложение предлагает набор мини-игр для развлечения за столом.

## 2. Целевая аудитория и платформа
*   **Платформа:** Веб (адаптивный сайт)
*   **Подход:** Mobile first разработка
*   **Пользователи:** Компании от 2 до 10 человек в барах/ресторанах/домашних вечеринках

## 3. Общая логика (Сценарий использования)
1.  **Вход:** Пользователь открывает сайт
2.  **Компания:** Вводит имена участников вечеринки
3.  **Счет:** Переходит в раздел "Сплиттер", вносит позиции чека и отмечает, кто что заказывал (или просто сканирует чек)
4.  **Расчет:** Приложение показывает, кто кому сколько должен. Один платит картой, остальные скидываются
5.  **Игры:** Компания переходит в раздел "Игры", чтобы развлечься, пока ждут сдачу или просто для веселья
    *   Играют в "Колесо фортуны" (определяют, кто не платит)
    *   Играют в "Тест на трезвость"
    *   Соревнуются в "Скороговорках"
6.  **Безопасность:** Если "Тест на трезвость" не пройден, приложение может временно заблокировать доступ к банковским переводам (чтобы случайно не отправить 100к вместо 1000) или звонкам бывшей

## 4. Функциональные требования

### 4.1. Модуль "Управление компанией" (Сессия)
*   **Создание комнаты:** При входе на сайт пользователю предлагается создать "вечеринку"
*   **Добавление участников:**
    *   Поле ввода имени и кнопка "+" (можно добавить хоть 1, хоть 15 человек).
    *   Возможность редактировать список (удалить, переименовать) до начала игр.
*   **Сохранение состояния:** Список участников сохраняется в памяти браузера (LocalStorage), чтобы при случайном закрытии вкладки не вводить всё заново.

### 4.2. Модуль "Сплиттер" (Разделение чека)

#### 4.2.1. Ввод данных (Умный калькулятор)
*   **Ручной ввод:** Поле для ввода общей суммы.
*   **Продвинутый режим (Киллер-фича):**
    *   Таблица "Позиции чека".
    *   Кнопка "Добавить позицию" (название блюда/напитка и цена).
    *   Возможность "прикрепить" позицию к конкретным участникам (галочки напротив имен).
    *   *Фича для ленивых:* Можно сделать быстрый выбор: "Разделить поровну на всех" (автоматически назначает цену блюда всем) или "Только для..." (вручную отметить, кто пил это пиво).
*   **Учет чаевых:** Поле "Чаевые" (можно указать процент или конкретную сумму, либо опцию "Без сдачи").

#### 4.2.2. Расчет и результат
*   Мгновенный пересчет долга для каждого участника по мере заполнения позиций.
*   **Итоговый экран:**
    *   Крупно: "Вася должен: 1500 ₽".
    *   Список всех участников с суммой к оплате (зеленый/красный индикатор, кто сколько должен).
    *   Кнопка "Скопировать долги" (копирует сообщение типа: "Ребята, по расчетам: Оля - 500₽, Дима - 1200₽, я оплатил картой, кидайте на Сбер/Тинькофф...").

### 4.3. Модуль "Мини-игры"

#### 4.3.1. Главный хаб игр
*   Меню с карточками доступных игр.
*   Отображение списка текущих участников (чтобы не забыть, с кем играем).
*   Кнопка "Мне повезёт" — запуск случайной игры.

#### 4.3.2. Игра "Тест на трезвость" (Числовая сетка)
*   **Суть:** Проверка когнитивных способностей (внимание и скорость реакции).
*   **Механика:** Сетка 5x4 (или 6x5 для усложнения) с числами от 1 до 20 в случайном порядке.
*   **Процесс:** Пользователь нажимает на ячейки строго по возрастанию (1, 2, 3...).
    *   Правильное нажатие — ячейка красиво исчезает или меняет цвет.
    *   Неправильное нажатие — анимация "встряски" и звуковой сигнал, ошибка фиксируется.
*   **Результат (Алгоритм оценки "индекса трезвости"):**
    *   Засекается время прохождения (таймер).
    *   Считается количество ошибок.
    *   Формула: (Базовое время / Время игрока) - (Ошибки * Штраф). На выходе получается число от 0 до 100%.
*   **Интеграция с "Ограничителями" (Вирусная фича):**
    *   **"Режим Трезвость":** Если индекс ниже 70% (или любого порога, заданного пользователем заранее), приложение может:
        *   Заблокировать (спрятать) кнопку "Перевести деньги" в модуле сплиттера (чтобы пьяный не отправил 100к вместо 1000).
        *   Включить "Режим полета" на 30 минут для звонков (блокировка ссылки на телефонного бота или скрытие кнопки "Позвонить бывшей").
        *   Показать предупреждение: "Ты не прошел тест! Утро вечера мудренее, иди спать".
    *   *Технически:* Блокировка реализуется через установку маркера в LocalStorage с временем жизни.

#### 4.3.3. Игра "Скороговорка"
*   **Суть:** Проверка дикции и артикуляции (или просто повод посмеяться).
*   **Интерфейс:** Крупный текст скороговорки. Кнопка "Записать ответ".
*   **Работа с микрофоном:** Запрос разрешения на доступ к микрофону (с пояснением, что запись никуда не уходит).
*   **База данных:** Встроенный список популярных скороговорок (10-20 штук).
*   **Логика проверки (Вариант А - Продвинутый):** Интеграция с API распознавания речи (Yandex SpeechKit, Google Speech-to-Text). Запись отправляется в облако, возвращается текст, сравнивается с оригиналом (процент совпадения).
*   **Логика проверки (Вариант Б - Бюджетный/Веселый):** "Режим караоке". Приложение просто показывает текст и записывает видео/аудио. После записи предлагает прослушать и предлагает друзьям за столом проголосовать (кнопки "Принято / Не принято"). Это не требует сложного ИИ и добавляет интерактива.
*   **Результат:** Если справился (или друзья проголосовали "за") — игрок молодец. Если нет — тянет действие.

#### 4.3.4. Игра "Колесо фортуны: Бесплатный чек"
*   **Интеграция:** Автоматически подгружает имена из модуля "Управление компанией".
*   **Дизайн:** Красочное колесо, которое можно крутить пальцем (физика вращения).
*   **Логика:** После остановки стрелки выводится попап: "Сегодня не платит [Имя]!" (или "Платит [Имя]!", в зависимости от выбранного режима игры).
*   **Кастомизация:** Возможность добавить сектор "Все вместе" (скидываются все) или "Банка" (штраф в общий фонд).

### 4.4. Расширяемость
*   Приложение должно быть спроектировано модульно. Добавление новой игры ("Правда или действие", "Я никогда не...", "Бутылочка") не должно ломать старый код.
*   Каждая игра — это отдельный компонент со своим маршрутом (например, `/game/corse`).

## 6. Этапы разработки (Roadmap)

### Этап 1: MVP (Минимально жизнеспособный продукт)
*   Создание компании (ввод имен).
*   Простой сплиттер (общая сумма / количество человек + чаевые).
*   Игра "Колесо фортуны" (рандомный выбор из списка имен).
*   Адаптивный интерфейс, темная тема.

### Этап 2: Расширение функционала
*   Продвинутый сплиттер (позиции чека, привязка к людям).
*   Игра "Тест на трезвость" (сетка 1-20).
*   Логика блокировки действий (банк/звонки) на основе результатов теста.

### Этап 3: Сообщество и контент
*   Игра "Скороговорка" (с записью микрофона и голосованием друзей).
*   База действий.
*   Добавление новых игр ("Правда или действие", "Я никогда не...").
*   Статистика и рекорды (кто быстрее всех собрал числа).

## 7. Заключение
Приложение должно быть максимально простым в использовании, даже для нетрезвых пользователей. Основная ценность — закрыть боль "дележа чека" и сразу предложить развлечение, оставаясь при этом в браузере без установки тяжелых приложений.
